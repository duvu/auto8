## Change Content Summary

- **Behavior**: Plugin validation is now fail-fast (throws at startup) instead of silent warn; `moduleRef.get(ClassRef)` is more idiomatic NestJS than `moduleRef.get("string")`
- **Safety**: Class-ref serviceToken is rename-safe; TypeScript will catch renamed service classes
- **Test isolation**: `PLUGIN_MANIFESTS_TOKEN` provider means `PluginRegistryModule.register()` doesn't mutate static state; each test gets its own manifests list
- **Cleanliness**: `jobHandlers`/`webhookEvents` declarations in manifests were never enforced; removed to reduce surface area and false safety signals

## Affected Flows

- **Runtime flow**: NestJS bootstrap — PluginRegistryModule.onModuleInit() now validates all connector service tokens at startup; fails fast with clear error if a connector service is not provided
- **Developer workflow**: Adding a new connector now requires a class-ref in `serviceToken` (TypeScript-safe) instead of a string literal

## Impact And Risks

- **Impact**: Breaking change to `PluginManifest` interface — any code creating manifests must update `serviceToken` to class ref, remove `module` from connector block, remove `jobHandlers`/`webhookEvents`
- **Risk**: Low — all affected files in this repo are in this commit; no external consumers
- **Mitigation**: All 9 plugin files updated; 66/66 contract checks pass; 64 unit tests pass; typecheck clean; build clean
